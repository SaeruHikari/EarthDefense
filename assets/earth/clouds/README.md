# Layered cloud data assets

Generated by `tools/bake_cloud_assets.py` using NumPy and Pillow, deterministic main/wind seed **260909**, high-cloud seed **260920**. The script performs all filtering, cloud-top gradient baking, filament generation, and wind-field construction offline. No Python or image synthesis is required at runtime.

These textures contain **linear numeric data**. Sample without `source_color`; do not apply gamma conversion, normal-map import conversion, alpha premultiplication, or alpha-border color repair. All four channels are independent data, including alpha.

| Texture | Dimensions | R | G | B | A |
|---|---:|---|---|---|---|
| `main_clouds.png` | 4096 × 2048 | Cloud coverage | Eastward cloud-top gradient, encoded 0.5 neutral | Southward cloud-top gradient, encoded 0.5 neutral | Optical thickness |
| `cirrus_clouds.png` | 2048 × 1024 | Sparse independent high-cloud coverage | Eastward gradient | Southward gradient | Reduced optical thickness |
| `wind_field.png` | 1024 × 512 | Eastward wind component, encoded 0.5 neutral | Southward wind component, encoded 0.5 neutral | Smooth spatial flow phase | Multiscale erosion/detail noise |

The wind components are dimensionless artistic velocity controls: `wind.rg * 2.0 - 1.0`. They combine latitude-dependent jets, local circulation, and smooth noise. They do not encode meters per second or a weather forecast. The field fades to zero velocity toward both poles. Longitude repeats continuously; latitude should clamp to a half-texel margin in the shader. A signed decoded wind component denotes motion toward east/south; texture advection normally subtracts velocity from the sampling coordinate to move visible features in that direction.

For normal approximation, decode `gradient = cloud.gb * 2.0 - 1.0`. This is the **height derivative**, not an already inverted normal: `normalize(radial - east_tangent * gradient.x * strength - south_tangent * gradient.y * strength)`. Start with strength **0.25–0.35** for the main layer and **0.15–0.25** for cirrus. Larger values can make the original fine cloud detail look embossed. Normal gradients are derived from a softened cloud-top estimate, not the Earth terrain, and smoothly reduced at the poles. Main/high gradient baking gains are 20 and 8 per source pixel, respectively; the encoded values are intentionally scaled for a shader strength control, not a physical height in world units. 8-bit neutral quantizes to 128/255, producing a negligible decoded offset of 1/255.

Main coverage is derived from the source grayscale cloud map with a smooth threshold at 0.115–0.84. Thickness combines a softened dense interior with the coverage field; use this in a bounded optical-depth/opacity model. Coverage and thickness are separate correlated quantities, so blindly multiplying them several times can erase thin wisps.

Cirrus is generated as **260 local feather-cloud plumes**, each with its own direction, finite length, bent ribs, irregular breakup, and tapered footprint. A faint domain-warped isotropic veil connects some nearby fragments. This avoids globally parallel latitude bands. It is not a duplicated, rescaled, or shifted copy of the main cloud image. Its lower mean optical thickness is intentional: this layer adds sparse high filaments and parallax without covering the entire planet in a second white veil.

Both cloud textures converge around the poles: inside v < 0.0015 (or v > 0.9985), R/A collapse to the latitude-ring mean and G/B become neutral. They blend back to the original data by v = 0.005 / 0.995. The main cloud pixels between rows 10 and 2037 are byte-for-byte unchanged by this polar repair. Longitude wraps normally.

Use `python tools/bake_cloud_assets.py --only clouds` to update only both clouds. Other options are `main`, `cirrus`, `wind`, and `all`. The wind RNG state is fixed independently, so revisions to the cirrus generator preserve the original wind data.

The import presets use mipmaps on all textures, high-quality VRAM compression on both cloud datasets, and lossless storage for the small wind field to retain smooth vector precision. Importing in Godot writes the final platform-specific cache paths and texture UIDs. `compress/normal_map=2` disables normal-map auto-detection because G/B are packed data. The gradient and coverage channels must remain available independently; do not force BC4 or normal-map BC5 compression. Use mipmap filtering; the runtime may select cloud quality by projected screen size.

## Statistics and verification

`BAKE_STATS.json` records dimensions, channel ranges and percentiles, file sizes, hashes, and longitude-seam comparisons. Initial uncompressed data:

- Main coverage mean **0.2560**, 95th percentile **0.9686**; optical thickness mean **0.2744**.
- Cirrus coverage mean **0.0489**, 95th percentile **0.2745**; optical thickness mean **0.0392**.
- Main coverage mean absolute seam-neighbor change **0.0352**, versus **0.0491** across normal horizontal neighbors.
- Cirrus coverage seam-neighbor change **0.0079**, versus **0.0070** across normal horizontal neighbors.
- Wind east/south seam-neighbor changes **0.00013 / 0.00040**. Flow reduces to neutral at the pole rows.

The longitude edge columns are adjacent samples of a periodic function, not identical duplicate columns; their continuity should be assessed against normal neighbor differences. The alpha channel is optical data and is not an RGBA preview opacity.

The bake was executed successfully and coverage previews were inspected. Actual GPU texture format, compression artifacts, lighting orientation, and gameplay frame cost must be checked after Godot import and shader integration.
