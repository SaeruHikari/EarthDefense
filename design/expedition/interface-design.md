## 一张图谱，两个阶段

阶段一保留紧凑地球核心：六个固定方向，每个方向四项科技，共 24 节点、72 个可购等级。玩家先理解工业、巡航、动能、光子、导弹、防御六个领域。阶段二沿同一空间骨架向外展开，中央旧科技的位置不变，避免进入远征后重新学习一张无关界面。

阶段二完整设计规模为六个分支、每分支十二项，共 72 项新增科技。当前示意只画每分支两个代表节点，合计 12 个外环节点；与阶段一合计 **36 个可交互研究节点**。中央“地球”是定位锚点，不计为研究节点。不能把示意的 12 个代表节点误读成完整阶段二目录。

## 层级与构图

采用深墨蓝背景、薄荷绿研究状态、少量金色里程碑与选中高亮。图谱是主视觉，右侧只保留一个节点详情面板；不把全图变成密集卡片墙。桌面详情宽度约 280 像素，窄屏移到图谱下方。分支直接标注名称，常态只显示重要节点标题，其余名称通过悬停、键盘焦点或点选查看。

节点尺寸表达对玩法的影响，不表达研究是否昂贵：

- 小节点：普通数值成长，圆点轮廓；弱化重复图标。
- 中节点：机制或生产能力，圆角方形，保留识别图标。
- 大节点：蓝图、阶段入口、代际进化等转折，较大双环轮廓。

参考大型节点图谱的空间层级与阅读方式，但节点轮廓、分支安排、色彩和图标组合为 EARTHWARD 自有界面，不复刻其他游戏的具体布局或资产。正式 Godot 版本可通过短时位置与缩放过渡展开外环，保留锚点连续性；减少动态效果设置开启时直接切换。本次交互预览以即时切换为主。

## 状态与操作

已研究使用实心填充与勾号；前置可达使用空心轮廓；未满足前置使用虚线与锁。状态同时有文字说明，不仅依赖颜色。示意的“前置可达”只表示条件满足，不模拟真实钱包，也不代表资源已足够购买。

悬停暂时预览详情，移出后恢复点选锁定的节点。点选或触屏轻触锁定详情；拖动不会顺带点选。锁定节点及其**直接前置**用金色高亮相应连线和节点，其余跨分支连接保持低对比，避免整张图同时发亮。详情中的前置项可点击跳到该节点。

空白区域拖动平移，滚轮以指针位置为中心缩放。放大、缩小按钮始终可用；缩放不把命中区压缩到难以点击。桌面节点命中区至少 34 像素，触屏约 44 像素；视觉圆点可以更小。小屏保留平移画布，焦点导航会把目标带入可视区域，不把几十个节点缩成无法辨认的点。

所有节点使用原生按钮与自然 Tab 顺序。方向键寻找相应方向最近节点，Enter 或空格锁定，正负号调整缩放。键盘焦点和触屏可以获得全部必要信息；悬停并非唯一入口。焦点变化与点选用简短的可访问文本播报，拖动和每帧渲染不连续播报。

示意仅提供局部设计选项：节点层级大小、关键/放大后全标签、分支标题显隐。它们不影响游戏数值，也没有保存或购买行为。

## 单节点详情合同

详情固定按以下次序组织：所属分支及阶段、名称与等级、作用范围、实际效果“当前→下一级”、消耗、直接前置、门槛、研究状态。

“作用范围”必须明确区分地球、全部战机的某一机型、永久蓝图、当前旗舰、当前远征舰队和需要实际安装的模块。尤其不能把研究到的蓝图展示为已经安装的模块，或把当前旗舰强化误写成所有旗舰都会获得。

普通数值直接显示玩家最终可用的数值或有单位的百分比；机制解锁直接显示新的能力。已满级节点写“已完成”，不制造不存在的下一等级。正式版本由同一效果计算函数提供实际当前值和预览值，不能在 UI 里另抄一份公式。

新阶段的关键详情保持如下合同：

- 外星光学望远镜：前置为击毁全部 8 艘近地母舰；首级永久开放六个远征目标，研究包含轨道阵列部署，不再额外收一次建筑费。
- 首艘旗舰：10×6 甲板，共 60 格，其中 42 格可建、18 格结构；首舰包有 2 座预装 Mk II 工厂。42 是可建格数，不是 42 个独立工厂槽，工厂真实占地决定容量。
- Mk III：对应机型的永久蓝图首次消耗 3 个将军核心。首位将军基础 1 核加首通额外 2 核，允许首次胜利后立即选择一个机型进化。
- Mk IV：对应机型的永久蓝图消耗 8 核，并要求占领 3 个星球、获得 2 种协议；主协议与辅助协议在整备时换装。
- 核心仅在首次研究蓝图时消费，阵亡补造同型号使用普通材料，不再次扣核心。“将军核心解析”许可不能额外拦截首胜后的 3 核进化路径。

上述核心费用与首舰尺寸来自总案；示意中的其他资源价格、部分当前/下级效果以及代表节点连线用于交互评审，后续以完整科技目录和数值表为准。正式完整树需要按三种机型分别表达永久蓝图归属，当前示意用“对应机型”压缩展示。

## 建议的数据接口

正式节点定义应分离静态目录、战役状态与 UI 布局。最小静态字段为 `id / stage / branch / importance / max_level / prerequisites / campaign_gates / scope / effect_ids / cost_curve / layout_anchor`。战役提供 `owned_level / unlocked / affordable / blocking_reasons`，效果系统提供当前值和下一等级预览。

节点状态应由稳定 ID 与战役数据推导；不能把画布位置或展示标题写作存档主键。连线根据前置引用生成，布局锚点只影响显示。隐藏阶段二时仍保留原节点状态，切换不会重新购买、销毁或回收科技。

稀缺资源成本建议进一步标注 `payment_scope = permanent_blueprint`，机型目标用 `aircraft_kind`；舰船局部升级则带 `flagship_id`。这些字段让详情、购买确认、阵亡补造与存档迁移共享同一语义。

开发存档库放在独立开发入口，科技图谱不承担存档管理。自动备份、命名快照与恢复验证按总案独立实现；此示意不提供假保存按钮，避免与已实际保护的通关档混淆。

## 落地验收边界

后续制作时应验证：24 节点与 72 等级和完整目录一致；36 节点示意不被误作为完整远征目录；任何有效前置都能通过指针与键盘导航；未解锁不穿透购买；实际资源不足准确解释；满级没有下一次扣款；不同宽度详情和操作区不重叠；长名称、极大数值、锁定/悬停切换不导致布局跳动；全图拖拽缩放不改战役状态。

迁移必须另验旧通关档的关键武器、工厂容量、产能与已购权益，而不是用本示意的示例等级覆盖。本轮仅完成提案、交互源码与必要文件回读，未打开浏览器执行交互验收，未启动 Godot，也未修改生产代码或发布包。原生游戏验收属于方案获得实施授权后的里程碑。
