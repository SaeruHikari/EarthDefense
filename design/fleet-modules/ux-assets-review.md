# 星舰模块：交互与美术制作专项方案

本文件是设计评审稿，不代表已经实现。依据本轮用户需求及现有 `starship_models.gd`、`combat_models.gd`、`starship_sidebar.gd`、`world_target_highlight.gd` 与批量渲染器审阅。

## 一、先明确产品边界

- 小飞机整体升级为护卫舰，仍由母星工厂和母舰自动生产补充，不增加护卫舰的直接购买按钮。旧动能、激光、导弹小飞机应成为三个基础配装预设，而非丢失其定位。
- 推荐统一、永久的“星舰系统开放”里程碑：第一次星舰发射井建成。此前保持第一阶段原有机型、界面与科技行为；开放时一次迁移。发射井后来消失，不撤销已经获得的能力。旧档已有井、造舰订单、星舰之一即可认定已经开放。
- 护卫舰补齐为前段 2 武器槽 + 中段 1 装甲槽、没有尾段，总共 3 槽。用户没有指定中段数量，这是本方案的建议默认；一个主装甲位保留选择，同时避免海量最小单位配装复杂化。
- 驱逐舰为 3 前 + 3 中 + 1 后，共 7 槽；母舰为 4 前 + 4 中 + 4 后，共 12 槽。插槽、武器实际开火数量、模型挂点、存档字段使用同一份规格数据，不能四处独立计数。
- 当前驱逐舰模型存在烘焙入船壳的 8 座装饰炮台，与 3 个实际主武器槽不一致。母舰舷侧“机库”同样只是刚性外形。必须拆除这些假炮位与封死的假舱口，重建能装备、开火、起降的部件。

## 二、点击舰船后的完整操作链

### 1. 选择与聚焦

沿用当前世界点选行为：悬停仍是薄荷青色轮廓；短按左键选中并平滑聚焦该船，后续保持跟随。移动超过已有拖拽阈值则是旋转镜头，绝不能同时选舰、换模块。建筑工具、科技画布与侧栏优先捕获自己的输入。

选中后的聚焦动画完成或稳定到可辨认大小，再用 0.15 秒淡入部位入口。这里不再自动进行第二次“配装镜头”移动，不调整 FOV、渲染画幅、星球位置，也不挤压世界视口。已有点舰聚焦与配装 HUD 是一次连续体验。

护卫舰显示“舰首 2 / 装甲 1”两个锚点；驱逐舰与母舰显示“舰首 / 中段 / 尾段”三个锚点。锚点是细线、小图标与已装数，不挂长名称、大数值面板。

### 2. 展开部位与插槽

点击部位只展开该段插槽，收拢另外两个部位。母舰不会同时挂 12 条连线，最多显示当前段的 4 个槽。锚点连接模型上的真实挂点；插槽按钮位置在船体附近排列，所有连线使用同一侧的阶梯布局，避免交叉。

每个槽默认仅显示当前模块图标及等级小点；空槽显示轻量加号。悬停槽时，真实装备部件以低强度青色轮廓响应，HUD 与船体建立一一对应。选中前段武器时可以短暂显示其朝向与射界轮廓，松开即退，不永久把场景画满射程圆。

### 3. 小型模块选择器

点击槽位打开唯一的、紧贴当前部位的局部选择器，建议逻辑宽度 320–360 像素、最大高度不超过 420 像素。无需第二个右栏、全屏舰船设计器或额外常驻详情页。

内容顺序固定：

1. 舰名 / 生产归属 / 席位 / 部位与序号，例如“工厂 #18 · 席位 03 · 舰首 1”。默认只修改该付费席位，批量操作必须另行选择并明确数量。
2. 当前模块一行。
3. 允许安装的模块网格：已研究可选、未研究灰显且可跳转科技节点、非法类别根本不列出。图标只能辅助，不让玩家记忆无法辨认的十几种符号。
4. 悬停或选择候选时，船体呈现半透明预览件；只计算预览，不换模型、不花资源、不改变伤害。
5. 显示最多 4 个重要属性的“当前 → 更换后”，并准确注明作用范围：本武器、全舰、所属护卫队或半径内友军。额外详细值可悬停展开，不能笼统写“火力 +50%”。
6. 核心、矿物、能量的实际花费、现有库存、确认后的余额；拆下模块去向和已安装数量。资源不足逐项标红。
7. 默认唯一主按钮“更换此席位 · 核心 N”；选择批量套用时改为“套用到 12 席 · 核心总计 N”，列明新增、复用、保持不变、不能应用的席位数量，不默认扩大作用范围。不再连续弹一个没有新信息的二次确认框。正在交战或航行无法施工时，按钮显示具体条件或“返回整备”，不能点击后才报错。

战斗中允许检查和预览，但不能靠快速换甲回满血、换推进器刷新冷却、换武器绕过射速。真正提交时再次校验舰船存在、模块已研究、槽位合法、资源、生产归属版本和整备状态；扣费、替换、保存是一个原子事务。重复点击与输入重放只能生效一次。

### 4. 运动、遮挡与退出

- 世界挂点每帧投影，屏幕标签加轻微阻尼，射击和船体摆动时不抖动。
- 船体背面的槽位仍可从所属部位入口访问，但使用虚线和“背面”小标，不能把实线端点穿透到船壳前面；被星球遮挡则整组淡出，禁止透过地球装配。
- 目标出屏后收起插槽，保留一个小型“返回所选舰”入口，不沿四个屏幕边缘铺开菜单；点它才调用原有聚焦。
- HUD 自身避让已有顶栏、右侧栏与底栏，挤不下时优先折叠成部位入口，不挪动游戏镜头。
- 按住空白处拖动时临时淡化连线、关闭未提交预览；不会丢失已经选中的舰。直接点另一艘舰则清理本舰预览、选择新舰。
- Esc 先退出候选预览，再关模块选择器，再收拢部位 HUD，最后走现有取消选中 / 退出跟随规则。点击空白处只是取消选择；取消或关闭预览不扣费。
- 舰船被毁、归属工厂被毁、存档重载时，失效的预览自动关闭，显示一句就地反馈，不能留下可点击的悬空按钮。

## 三、护卫舰生产席位、免费设计与付费实体

最终采用 `(ProductionSourceId, BerthId)` 作为护卫舰装备的持久归属键，每个生产者下的每个生产席位独立付费、独立保存三槽装备。当前飞行护卫舰只是这一席位的活动实体；阵亡后该席位自动补造新舰，继承已经付费的装备，不重复消耗核心。研究始终全局保留。

设计模板是免费保存的三槽设计图，可以命名、复制、预览和作为未来默认设计；模板不是已经支付的实体模块，不能因有一份模板就免费复制到整座工厂或全地图护卫舰。工厂或母舰扩容后出现的新席位初始使用免费基础装备，若要应用付费模块，需要为这些新席位分别支付实际安装费用。

点击任一护卫舰默认编辑它当前所属的具体席位，例如“母舰 #7 · 席位 03 · 舰首 1”。同一个局部选择器可以勾选“套用至同一生产者的其他席位”，无需打开额外面板；随后明确显示总席位数、需要新制造的模块数、已拥有可复用数、未变化数、不能整备数以及总核心与常规资源费用。用户看到并确认实际总价后才能批量提交，不能按一个席位收钱后免费复制，也不能显示单价却扣整组费用。

驱逐舰和母舰自身仍按 `(ShipId, SlotId)` 保存具体装备，同样每船每槽付费。多个同类模块是多个实体装备，必须满足数量与槽位合法性；免费设计模板不改变这一规则。

批量套用首先校验整组目标、资源、唯一模块上限和可用装备，作为一次明确的付费订单提交。提交时锁定模块与资源，显示逐席位状态；不能每更新一帧再次扣费。若存在不能整备的席位，提交前列明将进入等待队列的数量，并由用户的这次操作明确授权；不能悄悄略过而仍收取其费用。

已在机库的舰可先整备；外出旧版本在安全条件满足时分批返航，整备完成才应用新装备。已付订单在目标阵亡时转给原席位的补造舰，不再次收费；不能把相同订单同时应用到旧实体和补造实体形成复制。新生舰使用该席位已经完成或正等待完成的配置，避免外出舰与席位状态脱节。界面显示“已完成 4 / 12、等待返航 8”，不会让一次配置变更把所有防卫单位同时召回。

取消未完成整备时按订单里实际锁定的资源和模块释放，仅结算一次；已完成席位不重复退还其已使用部分。拆卸、回收和生产源永久消失的经济规则读取主方案的同一结算表，不在 UI 另算。底线是费用与归属透明、每个席位独立付费、自动补造不重复收费、扩容不复制已付模块、研究不会随普通单位死亡丢失。

存档必须保存生产者和席位的稳定 ID、已安装模块实体 / 当前槽位、待整备订单、已付费用、席位配置版本和活动实体应用版本。仅保存“工厂默认模板”不足以实现这套经济与自动补造。

## 四、首版建模与动画清单

以下统计物理资产交付物，科技等级不能虚增成多款新模型。本清单已与主方案的 16 个模块家族和兼容性统一；所有外观都是重新制作并保持当前阵营设计语言，不导入 EVE 原模型。

### A. 三种可模块化舰体

| 资产 | 制作内容 | 挂点 / 轮廓要求 |
|---|---|---|
| 通用护卫舰艇体 F01 | 把现有小飞机升级成有明确舰首、设备脊背和机腹的紧凑舰体；三种旧武器分别作为初始预设 | 2 个真实独立炮位、1 个装甲覆盖区；固定内置推进器，无可装尾槽。三种初始预设要从武器形态而非整船涂色区分 |
| 驱逐舰 D01 改造 | 保留现有狭长双壳、金属骨架与轴向负空间；拆掉装饰炮台，扩出真实甲板挂点 | 3 个前段主武器位、3 个中段通用位、1 个尾推进器；中段火炮要有错层射界，不互相穿射 |
| 母舰 C01 改造 | 保留当前环形开口和纵向脊柱；把舷侧假机库改成贯通的进出舱路径 | 前 4、中 4、尾 4；8 个前中段模块不塞进中间空洞；至少 2 个可动出入港，内部固定生产/停放能力不依赖重新开放甲板建造 |

护卫舰、驱逐舰、母舰现有尺寸关系维持 1 : 5 : 8。体积只需容纳表现上的内部机库，不追求把所有备用护卫舰同时塞进可见船壳，更不能在运行中渲染几百艘不可见内部备用舰。

### B. 16 个功能家族，对应 32 个可装配外观资源

规格统一：护卫舰 F 使用 S，驱逐舰 D 使用 M，母舰 C 使用 L。功能家族不是模型数；同一家族可能需要多个规格，装甲的三种家族也必须具有不同可识别结构，不能只把三色贴图算成三件成品。

| 数量 | 功能家族与实际装配资源 | 外形与装配要求 |
|---:|---|---|
| 2 | 武器伤害增幅：`damage_amp_s`、`damage_amp_m` | 通用蓄能 / 线圈套件围绕基础武器，兼容基础枪体。增幅不能使该槽停止开火 |
| 2 | 磁轨武装特化：`railgun_s`、`railgun_m` | S 紧凑双导轨，M 承力炮架、长导轨、线圈阵列；分别使用真实炮口 |
| 2 | 连续光束特化：`beam_s`、`beam_m` | 独立聚焦透镜、散热结构；中型体积不能只是小型等比放大 |
| 2 | 追踪导弹特化：`missile_s`、`missile_m` | 可开盖发射箱与真实离架点，不从船体中心生成导弹 |
| 1 | 中段重型火炮：`heavy_artillery_m` | 驱逐舰中段独立炮座，可转向；不占用三个舰首武器位 |
| 3 | 复合装甲：`composite_s`、`composite_m`、`composite_l` | 分层金属与陶瓷承力结构，三个规格分别覆盖对应舰体的装甲挂点 |
| 3 | 反应装甲：`reactive_s`、`reactive_m`、`reactive_l` | 外附阵列小块与可见间隙，受击响应有独立控制区域 |
| 3 | 烧蚀装甲：`ablative_s`、`ablative_m`、`ablative_l` | 叠层耐热板及深色接缝，与复合装甲保持轮廓差异 |
| 2 | 护盾电容：`shield_capacitor_m`、`shield_capacitor_l` | 外露能量环与低强度状态灯；驱逐舰和母舰可装 |
| 2 | 近防拦截：`point_defence_m`、`point_defence_l` | 小型高速瞄准机构，有独立射口；驱逐舰和母舰可装 |
| 2 | 维修单元：`repair_m`、`repair_l` | M 版自修设备、L 版舰队支援维修设备，功能范围与模型喷口 / 机械装置一致 |
| 1 | 机库扩容：`hangar_extension_l` | 仅母舰；侧向舱口 / 内部容积扩展结构，不能让驱逐舰获得生产护卫舰能力 |
| 1 | 指挥链路：`command_link_l` | 仅母舰；可辨认传感阵列 / 通信桅架，平时低强度扫描 |
| 2 | 巡航推进：`cruise_engine_m`、`cruise_engine_l` | 收束长尾喷口、稳定细尾焰 |
| 2 | 加力推进：`afterburner_m`、`afterburner_l` | 可见加力段、扩张喷口，工作时尾焰有明显加速变化 |
| 2 | 矢量推进：`vector_engine_m`、`vector_engine_l` | 多向喷口 / 可偏转喷管，与转向行为对应 |

数量校验：增幅 2 + 武装特化 6 + 中段火炮 1 + 装甲 9 + 辅助 8 + 推进 6 = **32 个模块装配资源**，覆盖 **16 个功能家族**。加 3 个模块化舰体与下节 5 项生产结构改造，共 **40 项制作 / 改造交付物**。此处按可直接装到挂点并验证的完整装配资源计数，不按底层 Mesh 文件或材质文件计数。

允许几何复用，但交付计数必须清楚：三种装甲可共享三个规格的底座，各自加复合层、反应块或烧蚀片形成九个装配场景；M/L 辅助可共享核心零件，并分别配置底座、轮廓尺度、接线和发射 / 维修端口。复用不能省掉任一被允许安装的型号，也不能做出 UI 允许但模型缺失的组合。

所有 T1 / T2 / T3 复用对应装配模型，仅用灯带、材质细节及少量现有结构的状态区分研究等级，不要求重复制作三级模型。舰体固有基础枪体、炮架和门体作为其所属舰体 / 结构的内部拆件交付，不另外虚增条目；基础武器必须保留可挂增幅套件、真实炮口和转向节点。

母舰可叠装护盾、装甲与近防，但**维修单元全舰最多 1 个、指挥链路全舰最多 1 个、机库扩容全舰最多 2 个**。前中段合起来计数，不能分段绕过；选择器、批量预检与保存校验使用同一上限。驱逐舰的 M 维修仅自修，母舰的 L 维修支援周围友舰。机库和指挥链路不提供 M / S 假型号。

### C. 五项生产与整备结构改造

1. 动能工厂机库适配件：保留建筑占地和主要体积，出口适配护卫舰包围盒，停放点与实际出厂坐标一致。
2. 激光工厂同上。
3. 导弹工厂同上。
4. 母舰双舷机库门、内部暗舱、引导灯、出入港安全通道作为一套结构资产。
5. 19 格星舰发射井内部起落台适配模块化舰体最大包围盒，避免新增炮台穿门。主占地不扩大。

这五项主要复用已有结构，工作量仍应独立验收，不能只在文件数里归入“复用”后跳过。

### D. 动画与效果交付

| 系统 | 动画要求 |
|---|---|
| 动能主炮 / 中段炮 | 炮塔先转向，炮口落在射界后发射；后坐与复位；无视觉朝向却从舰体中心发弹的情况 |
| 激光 | 透镜蓄光 → 真炮口出束 → 余辉衰减；停止射击不残留悬空光束 |
| 导弹 | 开盖 / 点火 / 离架再转弯，余烟短而清晰，不能在船壳内部横穿 |
| 护卫舰起飞 | 机库开门、引导灯、离架、加速、并入编队；母舰运动时从移动的真实门口飞出 |
| 护卫舰返航 | 对准移动母舰的回收窗口、减速、入舱、关门；接近阶段不用突然吸入或瞬移 |
| 模块安装 | 小型机械臂 / 舱内处理可用短动画暗示，完成时预览件转为实体；不必造完整机器人模拟 |
| 辅助单元 | 护盾局部受击、点防御瞄准、短距离维修连线、目标阵列小幅扫描；平时保留安静状态 |
| 推进器 | 巡航与加速两级尾焰、转向微喷、停车衰减；切装后尾焰只来自实际装上的喷口 |
| 受损 | 保留当前残血闪红，不能重新引入小飞机常驻血条；不要整支舰队永远发红闪烁 |

图标按这 16 个模块家族制作 16 个专属轮廓，再配五类模块大类图标、三种舰体图标和前中尾三种部位图标；S/M/L 与 T1/T2/T3 使用统一角标，不为每个规格另画一套图标。使用现有简洁矢量语言，明暗 / 轮廓 / 小类别角标共同编码，避免只靠颜色区分。

## 五、模型与逻辑的接口契约

所有舰体统一 `-Z` 前进、`+Y` 上方；舰体尺寸由唯一标尺规范化。至少应有这些命名挂点：

- `Hull/Sections/Bow/Slot_01...`
- `Hull/Sections/Mid/Slot_01...`
- `Hull/Sections/Stern/Slot_01...`
- 武器模块自身：`YawPivot/PitchPivot/Muzzle_01`，导弹可有 `Launch_01...`。
- 母舰：`Hangar/LaunchPort_01`、`RecoveryPort_01`、`Door_*`、`Clearance_*`。
- 火光、投射物、射界、HUD 引线全部读取相同挂点；不能分别写一个看起来差不多的位置。

每个模块的数据记录兼容槽型、作用范围、模型资源、挂点偏移和效果。配装预览与实际安装复用相同的兼容验证及属性解析。最终模型清单由数据自动导出，以免出现科技研究了一种武器但没有对应模型。

## 六、性能与验收原则

以下面数是制作预算而非已经测出的性能承诺：护卫舰艇体 LOD0 约 4–6k 三角形；驱逐舰 20–30k；母舰 35–50k。S/M/L 模块分别以 0.5/1.2/1.8k 为常用上限，非英雄镜头不叠加大量不可见面。LOD1 约三分之一、LOD2 约十二分之一；根据屏幕投影尺寸切换并有滞回，避免远处跳变。

静态舰体与模块实例共享资源；护卫舰按实际模型、材质、LOD 批处理。不要为一千艘护卫舰各创建多个 `_process()` 炮塔、Node3D HUD、灯光和维修粒子。只有选中 / 近景少量舰体展开细致动画与挂点视图，远景炮口与尾焰用实例数据。批量缓存必须考虑配置组合，但不能给每个可能的双武器组合都复制整个高模资产。

HUD 只为一艘选中的船更新，至多 3 个分段入口或 4 个详细槽位。模块属性在安装、科研、状态改变时重算缓存，不在每颗子弹或每帧反复遍历整个科技树。近景双武器必须真的有两个冷却 / 发射源；表现优化不能让两个武器只剩一个统计倍率。

首版通过条件：

1. 三种舰体槽数准确；所有允许组合能装，禁止组合无 UI 后门；所有可研究模块都有实物外观。
2. 两个 / 三个前段武器可独立选择类型、独立开火；增幅仍保留基础炮；导弹 / 激光 / 动能从真实炮口发射。
3. 新旧三种工厂出厂、母舰移动起飞与回收至少各一段原生录屏，门和舰体不穿插、不瞬移。
4. 12 槽母舰默认没有 12 条永久连线；1440×900、1920×1080、常见缩放下候选框不越屏、不盖住当前关键部件；开关配装保持世界视口参数不变。
5. 拖动、鼠标释放、切舰、Esc、失去目标、遮挡、资源中途不足、快速双击都走实际输入测试，不只测试数据方法。
6. 回放确认买模块前后费用与说明完全相同；退款/回库存规则不会重复发生；读档保留具体槽位和外出护卫舰的配装版本。
7. 同场景比较改造前后：无选中、选中护卫舰、选中 12 槽母舰、交战四种情况；分别记录 CPU/GPU/提交次数，不用空场高帧率代替交战验证。

建议落地顺序：先做一条护卫舰双炮与一个驱逐舰槽的真模型垂直切片，验证独立席位费用、免费模板与付费实体的区分、换装、炮口与性能；再做全舰体挂点与模型批量化；随后母舰机库生产和移动回收；最后补齐科技与外观件并完成迁移和压力验证。不能先做几十个科技节点，再用旧装饰模型和假数值凑成“已完成”。
