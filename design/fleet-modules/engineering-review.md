# 星舰模块化：工程与完整性审计

日期：2026-09-10。范围：只读审计与实施建议，未改动运行代码或玩家存档。本文是总体设计的工程补充，数值均为待实测的建议，不是已完成功能。

## 2. 最关键的经济缺口：外星点会断供

这是实查所得，不是推测：

- `scripts/game_state.gd:451-472`：中型 Boss 给 1 外星点；首阶段母舰给 3 外星点；小 Boss 给参数配置的核心，默认 5；cruiser 不给外星点。
- `scripts/battlefield.gd:1728`：持续进攻中的第一艘资源母舰被映射成 small_boss，其余 post_carrier 被映射成 cruiser。
- `scripts/battlefield.gd:2288-2300` 和 `scripts/expedition_director.gd:251` 的持续波次没有新的中型 Boss 外星点来源。
- `scripts/expedition_state.gd:471` 现有母巢/兵营奖励也只有矿物、能量、科研；当前远程母巢只是显示目标，缺少可完成的远程作战闭环。

因此，只要模块研究需要持续消耗外星点，就必须在新系统同时落实可重复获得的外星点。不能把全部新研究押在玩家第一阶段剩下多少点上，也不能要求先装完模块才能打唯一掉点的敌人。

建议：

1. 保留每个地球波次第一艘核心母舰的 5 核心掉落，不抢占、不改成仅掉外星点。
2. 每波指定唯一指挥母舰，默认给 1 外星点；普通持续母舰默认给 0 外星点，数量上涨不会使科研收入跟着线性/指数通胀。指挥外星点与资源核心为两个独立奖励字段，同一目标可同时承载两种奖励；完成击毁后各自只结算一次。奖励数值开放参数。
3. 科技主节点按单一经济账本支付外星点；模块制造/改装按核心与常规资源付费。研究解锁蓝图不直接生成无数模块。
4. 零外星点、零闲置核心的通关档，依然能靠已保留的地球防线打到下一个常规奖励；原始无模块的大舰/护卫舰需要能工作。可设置一次性的入门任务奖励，但必须持久化领取标记，不能在每次读档时返还。
5. 高阶节点费用必须根据实测的“每分钟有效外星点”和“地球经济分流后的核心余额”定标，不能仅靠很长的树看起来丰富。

原始第 125 波备份只读核对：24 外星点、378 核心，约 204,929 矿物、203,603 能量、74,076 科研；38 拦截工厂、18 激光工厂、13 导弹工厂。这份档并非零外星点，但是其他玩家和继续消费后的存档仍会遭遇断供。

## 3. 模块所有权与补舰：需要先定清楚

建议采用“每一件已付款改装件都有唯一所有者”的规则，区分两种载体：

- 驱逐舰/母舰：模块归属于具体舰 UID，不能同时安装到另一艘舰；换下后进入该舰的可复用备件账本。若首版暂不做备件包，可用明确的固定拆解返还率，但不可依实时折扣产生套利。
- 自动补充的护卫舰：模块归属于生产源下的持久化 berth_id（编制席位），该席位的当前护卫舰使用它。被击毁后新船继承同一已付款配置，不会再次扣核心；新增容量产生空白席位，不能复制已装模块。这样保留可承受的战损与自动补舰，又避免一枚核心自动改造整个帝国。
- 点击某艘护卫舰改装就是改装其归属席位。卡片写明“本舰／母星工厂 X 的第 N 编制”，让死亡后的配置归属可理解；可有“同源另外 N 席位”小选项，显示总核心成本，逐个占有对应组件，不用另开全屏管理页。
- 初始基础武器/普通船壳属于船体自带功能，不伪称免费模块。空前槽仍有基础火炮；安装伤害放大模块增强该硬点，安装武装特化模块将该硬点转换到已研究的武器类型。这样护卫舰和驱逐舰不会因为核心暂缺而成为无火力空船。
- 第一期不允许跨载体偷偷复制。拆卸、转移、批量改装、取消订单与造船死亡同时发生时，账本满足：每个 OwnedModule 只在一个槽位或库存；每个 berth 只有一个 active_ship_uid；每个 spawn vacancy 只补一次。

这一规则是建议，需要在总体方案中明确写给用户；不能当作用户已经指定的规则。

## 4. 推荐数据契约，渐进改造即可

不必全项目换 ECS。新建一层数据定义和服务，把现有 Dictionary Actor 分批接入：

| 类型 | 最少字段/职责 |
|---|---|
| ShipDefinition | id、ship_class、model_id、base_stats、size_reference、sections、base_weapons、production_policy；护卫舰/驱逐舰/母舰都引用统一定义 |
| HullSection | section_id（front/mid/rear）、model_anchor、slot_specs；只做真实存在的段，不让护卫舰虚构尾槽 |
| SlotSpec | stable_id、allowed_module_tags、weapon_anchor_id、model_attachment_id、scale_class、base_weapon；前中后兼容规则只在这里定义一次 |
| ModuleDefinition | id、研究节点 ID、类型标签、适用舰级、tier、install_cost、modifiers、abilities、mesh_id、VFX_id、stacking_group；禁止在 HUD 和战斗代码各写一份效果 |
| LoadoutDefinition | 载体及版本、每个 slot_id 对应的 owned_module_id、基础武器预设；可计算稳定 hash，供数值缓存和渲染分桶 |
| OwnedModule | uid、definition_id、paid_cost_snapshot、owner_ref、slot_id/备件状态、transaction_id；科研解锁只改蓝图账本，不新增这里的实物 |
| ShipActor | 现有 UID、definition_id、source_ref、loadout_ref、hp/max_hp、shield、world transform、velocity、movement_mode、hardpoints、AI 状态；仍可用轻量 Dictionary + 索引 |
| ProductionSource | source_id、source_type（surface_factory/carrier）、world pose/velocity、berths、replacement_queue、launch/recovery/repair anchors、active/disabled；统一缺额、补机和归属 |
| ProductionBerth | stable_id、source_id、base_preset、loadout_id、active_ship_uid、replacement_progress、occupancy_state；容量变化只增减空席，不能隐式抹掉在飞船和付费配置 |
| StatResolver | resolve(ship_definition, phase1_tech_snapshot, loadout, tuning_revision) → cached CompiledShipStats；独立 resolve_weapon(hardpoint)，清楚区分船体/局部/光环属性 |
| RefitService | preview/validate/commit/cancel 四个入口，操作前后二次验证目标、研究、兼容性、余额和 revision，单次事务扣款+转移+持久化 |
| CombatSpaceQuery | query_targets、line_of_sight、body_occluders、swept_projectile_hits；统一地球和自由空间真实世界坐标，保留空间索引 |

编译属性只在研究、配置、工程参数、影响本舰的支援单位集合发生变化时重算。资源每帧增加触发 changed 不应导致所有舰的数值重编译。

推荐计算顺序：船体/基础武器 → 继承的第一阶段科技 → 本硬点模块 → 本舰辅助/装甲/推进 → 外部支援光环 → 各属性安全边界。伤害、射速、弹数、AOE 必须分开，不能把“百倍战力”变成每项都乘 100 导致 DPS 乘上万、移速乘百的错误。百分比减伤有明确上限，叠加同类模块有总和/最强者/递减等显式规则；避免光环递归放大自身。

## 5. 实际战斗与航行闭环

### 5.1 从两个炮口到真实两套武器

- 每个硬点有自己的炮口、朝向、转速/射界、目标 UID、冷却和投射物属性。不能把总伤害乘二后仍从中心只射一发。
- 所有攻击从挂点的真实世界变换发出；模型炮台朝向与发射方向同源。
- 当前小飞机三种类型迁移到三种护卫舰基础预设。保留已付费科技权益；升级前原战力不变，升级时把原船总 DPS 拆到双硬点，之后靠新模块产生增量，不因“多一个出弹点”隐藏翻倍。
- 老三联齐射的副弹 50% 权重、激光阵列、导弹齐射应在迁移预算中明确记账，不能逐硬点重复完整套用。画面可错相开火，既看到双武器，也不因同时齐射把弹幕和 CPU 开销加倍。
- 驱逐舰三前炮分别选择目标；中段火炮占用真实中槽与炮位，付出失去辅助/装甲的取舍。
- 防御辅助单元必须真正执行点防御、干扰或导弹拦截中的对应行为；仅显示“防御 +10%”不算完成一个有描述技能的模块。
- 在途炮弹预留预期伤害，命中/失效后释放预算；避免全部驱逐舰浪费一轮打低血量小机。

### 5.2 母舰移动与护卫舰管辖范围

所有范围需要分开命名：护卫舰单炮射程、护卫舰离母舰最大活动半径、母舰紧急出击触发半径、驱逐舰有效远程武器距离。用户“五倍”应绑定明确的护卫舰管辖基准，避免绑定某架装备不同推进模块的护卫舰而反复波动。

- 停泊时按自有近防圈巡逻，不能把地表工厂护卫舰自动抽走导致地球失守。
- 远航前召回所属护卫舰，远航中默认留在机库；只在近威胁越过触发区、预计能完成拦截并返航时发射。
- 触发半径与结束半径分开、有数秒最短任务时间，防止在边界反复起落；目标从哪个方向来，优先对应方向的可用出口。
- 起飞继承母舰速度，加上机库出口相对速度；归航追踪未来截获点而非母舰此刻位置。接近机库时才进入母舰局部坐标，离舰后保持独立世界坐标。
- 母舰准备高速移动时等待回收短宽限时间；仍在近战的舰只显示明确状态，不无条件瞬移回收。必要时巡航降速以确保回收，规则可配且可被玩家预见。
- 母舰损毁后：在飞护卫舰优先寻找有空泊位的最近同阵营母舰/母星工厂；没有来源则进入有限自主作战和返航逻辑，不能报错、立刻消失或无限自动复制。
- 低血冲撞/死亡自爆保留护卫舰已有体验，明确不默认让母舰同样殉爆；装甲与维修不会通过更换模块瞬间满血。

### 5.3 整个战场持续运行

地球留守防线、远航舰队和近地敌方母舰同处真正世界坐标，切镜头不暂停其他战场。新系统首版至少要有一个可下达的远航目标、途中敌人、驱逐舰远击、逼近后舰载护卫舰近防、回收/损失补舰；否则只做静态停泊舰的模块演示，仍是用户批评的半成品。

不要求首版顺便重建六星球特殊 Boss、舰体甲板建造或复杂编队编辑。已删除功能不应因新系统绕路复活。

## 6. 槽位 HUD 与模型接口验收

交互不是三套面板：点击选中舰船 → 稳定聚焦/跟随 → 舰艏/中段/尾段少量锚点 → 点击该段 → 只显示该段槽位 → 点击槽位 → 一张靠近目标的小改装卡。卡片给出当前值→更换后值、核心与常规资源总价、已研究可装项、暂不能装的原因。

- 护卫舰仅艏/中段；驱逐舰/母舰才有尾段。默认不同时展开母舰十二个大标签。
- 锚点由 HullSection/SlotSpec 定义和实体变换投影，不按屏幕固定百分比猜位置。
- 遮挡/屏幕外/过小目标不展示密密麻麻锚点；被地球遮挡的槽位不可穿透点击。舰体跟随与科技侧栏都不能改视口尺寸。
- 鼠标拖拽优先既有旋转手势，不被插槽点击劫持；右键/Esc 逐层退回；失去目标或目标死亡立即撤销未提交卡片，不能把付费操作应用到下一艘自动选中的船。
- 已付款改装排程清楚显示“等待返港/改装中/完成”，短暂锁定该舰；战斗中不能靠装甲互换刷血、换武器重置射击冷却、换电池刷护盾。
- 模型至少具备真实炮座转动/后坐、双/三炮口、母舰机库开闭/护卫舰进出、装甲模块外观变化、推进器形态和尾焰区别。不同护卫舰预设与模块通过可见的大形体而非微小贴花区分。

## 7. 解锁与存档迁移

根据主方案统一：以“首次建成星舰发射井”作为永久里程碑。望远镜研究仍先开放发射井建造；首次发射井建成后，模块分支、护卫舰称谓/模型升级、部位 HUD、母舰编制和新生产规则一起开放。不把“是否目前还有一座发射井”当永久解锁标记，拆掉最后一座井不能把已升级护卫舰变回旧飞机。迁移已有发射井、已付款星舰订单或已造星舰的旧档时据此标记解锁，重复加载不重发权益。

迁移流程：

1. 读取旧存档到独立候选对象，先验证旧结构；记录源版本和迁移标记。
2. 未到星舰阶段：继续旧飞机路径，参数、工厂计时、科技、DPS、血量、敌方调度保持原样，不免费触发升级。
3. 已到阶段：为现有工厂稳定生成 production source/berth；保留 UID、factory_site_id 关联、席位、当前位置、朝向、速度、生命比例、瞄准、机库状态与补舰进度。相机/观战目标 UID 继续有效。
4. 现有驱逐舰、母舰保留 UID、生产订单、已付款金额与集结位置，补入基础战斗和空模块状态，不能重新扣一遍造船费。
5. 第一阶段科技原账本保留；新的模块研究不会再次索取同一旧节点，也不把旧科技简单清零折现。
6. 原存档资源建筑核心升级记录原封保留。迁移产生的入门权益有唯一领取标记；保存、加载、再次迁移后无重复发放。
7. 校验模块归属唯一、硬点兼容、来源存在、舰只/席位一一对应、订单/资源和配置版本，再执行原有临时文件写入-校验-替换流程。错误返回时保留原档，不部分扣款或部分升级。

目前顶层存档 version 3（`main.gd:925`），ExpeditionState version 4（`:528`），StarshipFleet version 2（`:215`），ExpeditionDirector runtime version 4（`:321`）。不能只升级其中一处；跨层引用校验要同时跟进。

原 125 波通关档继续保留原始只读备份；LaunchDebug 当前的后续进度也要另备份，不能为了演示新系统反复重置。交付应演示从玩家实际当前开发档迁移一次、关闭、重开接着玩的结果。

## 8. 性能策略与验收方法

- 复用已有合批与空间索引；护卫舰 hull + 可见模块按共享 mesh/material 分桶，不按每艘 loadout ID 建独立材质。最多按真正改变外形的 signature 缓存，不为纯数值等级生成不同几何。
- 大舰数量少，可使用独立炮塔动画；护卫舰远处只做批量模型/炮口效果，选中近景才提高可见活动件的细节。未出击的机库编制只保存轻量状态，不为每个机库单位创建渲染节点与寻敌过程。
- 原目标分配约 0.35 秒一次；长射程查询容易跨越大量 2.0 单位网格，不能按“巨大包围盒每格遍历”放大成本。大舰/远程目标建立较粗层级索引或活动战区候选表，炮弹精确碰撞仍用局部网格。
- 研究/换装影响属性时做 revision 缓存；光环每 0.2–0.5 秒更新邻居集合，固定最高/递减堆叠，不每炮扫描所有母舰。
- 第一阶段前后在同一存档、同一相机、同一画质、同一随机种子比较 60 秒，分别记录 95/99 分位帧时间与 CPU 子项；已有数千飞机巡航和交战回归必须跑。避免用 Headless 数千测试条数代替真实 GPU 渲染下的 CPU 卡顿检查。
- 新场景分档 500 / 1000 护卫舰，加 12 / 32 驱逐舰、2 / 4 母舰，以及对应敌人；独立统计寻敌、武器、弹道、回收补机、模块更新与渲染提交。不能虚报 4090 就能保证 300 FPS，CPU、分辨率和场面都需记录。
- 交战突然发生、一次齐射、区域内大量船被 AOE 击毁、同帧补位、快速打开模块/科技、保存读档是重点卡顿点。

## 9. 建议实施次序与每一步“完成”的定义

### A：数据/经济/迁移底座

完成定义、兼容矩阵、研究和装备账本、可重复外星点来源、只读预览→原子支付、保存迁移；在现有 UI 内显示可验证的实际结果。先跑旧档迁移、零资源通关档可继续获得奖励、重复加载无复制、坏档原子拒绝。不能只交一堆空类。

### B：第一条完整纵向玩法切片（同时包含三舰职责）

只用基础动能/强化动能、一个装甲、一个母舰机库辅助和一个推进模块，但必须全部有真实部件、正确槽位、实际战斗属性和支付成本。玩家可研究、选舰、改装；一个母舰 + 一个驱逐舰组成远航单位，母舰产护卫舰，驱逐舰远击，敌人逼近护卫舰出击，损坏回收、损毁补位、回收改装、关闭重载能继续。未完成这个片段前，不批量扩写几十个模块。

### C：扩足初版内容与表现

在同一完整链路上扩到最终模块目录、全部前中后槽位和三种护卫舰预设，完善各武器/支援可见区别、批量同源改装小选项、科技树布局与所有错误原因。增加表现不另建冗余页面；真实点击锚点能看到舰体对应位置。

### D：玩家档全流程调平、性能、交付

必须用正常经济玩完研究→生产→改装→远航→接敌→返港/补舰→再研究，另测地球同时受攻；说明第一阶段科技继承和第二阶段新增效果。测试具体体验与不变量，输出可重现日志和短录屏/截图，不把“XX 项通过”当完整性证明。

默认一井生产驱逐舰 30 秒 + 母舰 90 秒，母舰随后 6 秒起飞 + 18 秒集结，最早约 144 秒，休整默认为 150 秒。学习新系统和建井还需要时间，因此不要承诺玩家首次打开系统就能在 150 秒内从零学会造出并改好整队。应允许原有暂停、清楚显示队列与时间，验证正常手速能完成至少一个合理整备目标；必要时平衡造舰时长，不能偷偷扩张五回合或打开 UI 就重置休整。

## 10. 必须明确测到的结果

1. 到解锁节点前，所有第一阶段玩法、数值、机型、HUD 和存档行为一致；解锁后同一批实体升级且来源不丢失。
2. 任意研究节点的可见前置都真实存在且可达；零外星点也有可赚取的下一步，不形成战力/研究相互依赖死锁。
3. 前二/前三武器真实独立开火，中槽火炮真实可见，母舰没有意外获得直接主炮；硬点不朝侧面穿模开火。
4. 增伤模块只改变声明的硬点/全舰属性；科技、光环、移速、减伤无重复或无限叠加。
5. 核心扣款、更换、取消、受攻击、击毁与保存同帧发生时不重扣/复制/刷血；损失护卫舰只补该一个付费席位。
6. 远航中驱逐舰先接敌，舰载护卫舰只有近威胁才出击；边界处不反复开关机库，母舰运动也能真实回收；同方无碰撞。
7. 地球持续作战与远航互不暂停；世界坐标、遮挡、投射物、第一人称、舰体点击聚焦全部有效。
8. 随机在造船/起飞/回收/改装/射击中保存再加载，订单、资金、模块、HP 比例、UID 和归属一致；原通关备份哈希未变化。
9. 部位 HUD 不遮主战场，不重设相机或画幅，不劫持拖拽，不因目标移动或死亡把购买落到另一艘舰。
10. 在真实渲染场景记录基准前后 CPU 分项与卡顿分位，保证旧大机群优化没有被模块实例化、长射程或 VFX 反向破坏。

## 11. 与主方案对齐的实施补充

主方案初版目录为 16 个模块家族 × 3 个等级，外星点研究梯度 1 / 3 / 7；各舰核心安装基数护卫舰 1、驱逐舰 2、母舰 2，使用持久化编制位继承规则。上述价格应统一引用定义表并保留工程参数，不写入多处分支。3 级全家族理论共 176 外星点，原 125 波剩余 24 点不足覆盖全树，这正是必须恢复可重复外星点收入的理由；初级16点已经可做全部入门横向选择，后续点数来源与解锁节奏必须实玩定标。

垂直切片必须补齐三个当前完全缺失的运行能力：

1. **移动生产源**：母舰具有固定内部机库及生产席位，不恢复旧甲板工厂建造；每席位的欠额、建造进度、已付款配置、维修和 active_ship_uid 都持久化。母舰 world pose / velocity 在每步更新后供离舰与归舰计算。机库舰只不参与寻敌/碰撞/渲染；离舰时才进入战斗 Actor 索引。若母舰被摧毁或换模块降低容量，按清楚的托管/迁移/超额回收规则处理，不能无声删掉已付款模块。
2. **星舰实战与敌方目标支持**：驱逐舰新增 hp/护盾/装甲/独立炮位，敌军候选不再只包含 EarthBattle._drones；新增统一阵营 actor lookup 支持驱逐舰、母舰、护卫舰和远方敌舰。敌人能选择和命中大舰，其 AOE 也能伤到附近舰只；舰死只结算一次并解除其在途目标/护卫归属。沿用真实世界坐标、视线阻挡、敌我射程公平与高威胁优先，不能出现我方有数值但永远不会被选中受伤。
3. **舰队基础出航指令**：现有 StarshipFleet 仅有从发射井到固定停泊位，没有玩家能用的远航命令。首版在选中母舰的小型上下文 HUD 中提供“前往已观测目标 / 返航 / 停泊”三个动作，并能让驱逐舰简单加入该母舰的护航集合；点击星球仍只切镜头，不能偷偷变成下达危险移动命令。母舰是航行锚点，驱逐舰按偏移护航并保持远射，近威胁才放出护卫舰；一个母舰单位的舰队集合保留于存档。先支持基础集合，不重建已删除的手动小飞机编队编辑器。

第一条正式演示：用真实资源在地球发射井生产母舰与驱逐舰 → 科技树研究一个模块 → 点击舰艏/中段/舰艉实体挂点并装入 → 母舰内部自动补满几个护卫席位 → 在母舰上下文中选已观测目标出航 → 途中远敌先被驱逐舰攻击 → 近敌触发机库出击 → 敌人击中我方大小舰 → 一艘护卫舰阵亡后由原母舰原席位补造 → 残伤舰真实回收维修 → 保存重开继续在原位置航行 → 返回地球停靠。只有这一链路已经成立，才扩48项级别内容和最终美术；只完成科技图/装槽卡/静态数值预览不算一版落地。
