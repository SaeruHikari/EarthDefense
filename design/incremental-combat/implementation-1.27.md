# 1.27 实施与验收状态

本文记录当前源码已落地的边界及验证证据。它不是最初方案的完成声明：远航仍关闭，规模性能与原生 UI 的最终统一验收须另行记录。旧版本文档中的节点总数、JSON 调参、GDScript 入口与编辑器宿主性能不能代替当前实现。

## 当前实现

### C# 业务与正式数值源

- 游戏入口、领域、战斗、渲染、交互、存档均为 C#；Godot shader 保留。运行时不加载 GDScript，不借 C# 回调旧 GDScript 实现业务。
- 正式数值为 `data/domain` 下 64 张 CSV。目录结构、引用、数值类型、范围和科技循环在载入时校验；当前数值读取失败不会自动套用旧 JSON。
- 历史 JSON 只用于明确的存档迁移映射或测试 fixture。既有研究 ID、付费权益与永久特性等级保持，当前效果依新 CSV 重新计算。

### 独立科技与就近布局

常规树共 299 个 max=1 节点：246 小、41 中、12 大。小点只付科研；三项容量中科技各 +1，研究容量总额最多 +3。六条终局后继各有最多 10000 个独立等级，用压缩持久化和最多六节点的历史窗口展示；常规全解锁作弊不替玩家购买后继。

### 巡航与首清连通性

正式巡航基数和远端基数各乘 1.5；32 个相应研究增量各乘 1.5。`values`、人读说明与 `effect_definition` 三处同步。默认工程覆盖倍率仍为 2，保留 0.25–8 的调节范围；兵种速度、生命、伤害、武器局部射程和母舰护甲相性没有借本次改动一起上调。

首清前通过真实 `PurchaseGroup` DAG 可购买的研究共 159 项。`C_G1` 在第 0 阶段可达，行动半径 24 足以覆盖半径 21.65 的近地母舰；未依赖首清后的 `C_A2/C_A3/C_G2`。原问题同时包含过小的横向防区和动能对能量层免疫，后者是已确认的玩法规则，继续保留。

首清前工厂覆盖半角由动能 17.5°、激光 21.8°、导弹 25.3°分别增加到 28.6°、35.7°、41.4°。现有工厂范围提示及「母舰攻坚」说明补充：动能无法穿透能量层，激光破盾后可接力。地表覆盖与高度数值仍来自 `Battle.GetFactoryCoverage` 的真实能力包络。

`tests/ProgressionReach127` 已完成 **422 项检查，0 失败**。该测试预置资源作为试验输入，但全部研究通过正常购买和前置校验取得，没有设置全解锁标志或直接填研究节点。覆盖范围如下：

- 九机型在各个合法研究阶段的范围矩阵；尚未解锁的机型不会伪造为已开放。
- 原始工厂位置、八母舰均存活时，三种基础机均可完成飞行及实际伤害；动能由真实激光剥离能量层后接力。
- 八固定母舰方向 × 三种基础机，工厂位于新角边界的 90% 位置，共 24 组真实起飞、移动、瞄准、射击与伤害；目标位置取实际母舰生成数据。
- 真实角边界内允许、边界外拒绝，没有把多个能力配置拼成一个虚假的覆盖承诺。
- 半径 56/88/128 的三层外推，各三种基础机完成斜向实飞和伤害；需要破盾的非激光单位使用激光支援。行动半径仍为 62/96/140，上一层不能越级覆盖下一层。

这些是隔离的战斗功能检查，不是完整自然经济通关时长或密集战场性能测试。本地记录为 `artifacts/progression127-reach-before.log`、`artifacts/progression127-reach-after.log`。

### 标准优化源码 player

游玩路径已经由编辑器宿主切换为官方 Godot 4.6.1 .NET Release 模板，采用标准 `dotnet publish -c ExportRelease -r win-x64 --self-contained true` 输出。没有修改 Godot 安装中的 DLL，也没有把 Release API 塞进 Debug API 目录作为最终方案。

官方模板禁用 `--path`、`--main-pack` 和位置式场景覆盖。当前方案把原版 player 放到项目根目录，利用其标准同目录项目查找规则读取当前源码；配套输出放 `data_Earthward_windows_x86_64`。顶层 `_custom_features="dotnet"` 负责启用标准非编辑器 .NET 初始化。原生测试用游戏用户参数 `--native-scene=res://tests/managed_*.tscn`，只在确实包含测试类型的发布中允许，且每进程只路由一次。

### 交战与界面提交优化

- 舰队容量统计从“每厂扫描全军”改为一次遍历聚合，保留重型双编制、实际缺编和补造规则。
- 资源/容量 HUD 数据按 15 Hz 复用，波次、配置变更和操作会失效刷新；按钮命中、悬停与动画仍逐帧。建筑静态成本/锁态、字体宽度、截断与悬停排版也有缓存。
- 爆炸 core/shell/8 sparks 合为三个 MultiMesh 组，世界/球面光束各一组。稳定光束几何、缓冲和包围盒复用，未删火花或更改生命周期与发光强度。
- 特效专项原生检查曾完成 715 项、0 失败，并对五个动画时刻做像素对照；这是特效专项证据，不代表全战斗最终帧率。
- 战斗与渲染的其它缓存、并行和存档性能调整由各自专项记录与最终统一测试确认。
